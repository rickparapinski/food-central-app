# food-central — Development Guide

## What this app is
A mobile-first PWA for weekly meal planning, pantry management, barcode scanning, and macro tracking. Solo user, self-hosted.

## Stack
- **Framework:** Next.js 16 (App Router, Turbopack)
- **Database:** SQLite via Prisma 7 ORM + `@prisma/adapter-better-sqlite3`
- **UI:** Tailwind CSS + shadcn/ui (mobile-first)
- **AI:** Claude Haiku (`claude-haiku-4-5-20251001`) — server-side only
- **Barcode scanning:** `@zxing/browser` (camera API, runs in browser)
- **Barcode lookup:** Open Food Facts API (German product coverage)
- **OCR:** Claude Vision (Haiku) — for photographing nutrition labels

## Hosting
- Runs in an LXC container on a homeserver
- Exposed publicly via Cloudflare Tunnel + custom domain
- No auth needed (solo user)
- Data lives in `/data/food-central.db` (SQLite) and `/data/photos/` (label images)

## Core features (build order)
1. **Pantry** — scan barcode → Open Food Facts lookup → store product with macros
2. **Unknown barcode flow** — scan fails → photograph Nährwertangaben label → Claude OCR → save to custom product DB
3. **User profile** — macro targets (kcal, protein, carbs, fat) + food preferences (dislikes, allergies, dietary style)
4. **Meal planner** — "plan my week" → sends pantry + profile to Claude Haiku → returns 7-day meal plan with recipes
5. **Grocery list** — auto-generated from meal plan minus pantry contents
6. **Macro tracker** — log meals from plan, track daily progress vs. targets

## Key product decisions
- **Language:** Product names stored in German (as found on German packaging/Open Food Facts DE), with English translation stored alongside. UI is in English.
- **Recipes:** Not German-specific — contextually sensible given available ingredients. Generated by Claude Haiku.
- **No backend-less approach:** API keys and AI calls go through Next.js API routes (server-side). Never expose the Claude API key to the browser.
- **Single container:** Next.js server handles both frontend and API. No separate services.

## Database (Prisma 7 + SQLite)
Schema is live in `prisma/schema.prisma`. Models:
- `Product` — barcode, name_de, name_en, calories, protein, carbs, fat, source (`open_food_facts` | `custom`), photo_path?
- `PantryItem` — product_id, quantity, unit, added_at
- `UserProfile` — macro targets, preferences (JSON string), updated_at
- `MealPlan` — week_start, plan (JSON string — 7 days × meals), generated_at
- `GroceryList` — meal_plan_id, items (JSON string), checked_items (JSON string)
- `MacroLog` — date (YYYY-MM-DD), meal_name, product_id, quantity, logged_at

Prisma 7 notes:
- Generator: `prisma-client` (not the old `prisma-client-js`) — outputs to `src/generated/prisma/`
- Import client from `@/generated/prisma/client`, not `@/generated/prisma`
- Requires a driver adapter: `PrismaBetterSqlite3` from `@prisma/adapter-better-sqlite3`
- Client instantiation: `new PrismaClient({ adapter })` — see `src/lib/prisma.ts`
- Config in `prisma.config.ts` (datasource URL lives here, not in schema.prisma)
- Migrations: `npx prisma migrate dev --name <name>` (dev) / `npx prisma migrate deploy` (prod)
- After schema change: `npx prisma migrate dev && npx prisma generate`

## AI usage (Claude Haiku)
- All Claude calls happen in `/app/api/` route handlers
- **Meal planning prompt:** Include pantry items, user macro targets, food preferences, and week start date. Ask for structured JSON output (7 days, each day has breakfast/lunch/dinner/snack with ingredients and macros).
- **OCR prompt:** Send nutrition label photo, ask for structured JSON: `{ calories, protein, carbs, fat, serving_size, serving_unit }`. Label is in German — model handles this well.
- Keep system prompts in `/lib/prompts.ts` for easy iteration.

## Mobile-first UI notes
- All interactive targets min 44px height
- Bottom navigation bar (not top) for thumb reach
- Camera sheet opens from bottom on barcode/photo actions
- Use `shadcn/ui` Sheet and Drawer components for mobile overlays

## Environment variables
```
CLAUDE_API_KEY=
DATABASE_URL=file:/data/food-central.db
PHOTO_STORAGE_PATH=/data/photos
```

## Deployment (LXC container)
- Build: `npm run build`
- Run: `node server.js` or `npm start` (port 3000)
- Nginx or direct Cloudflare Tunnel → port 3000
- Prisma migrations: `npx prisma migrate deploy` on container start
- Backup: `sqlite3 /data/food-central.db .backup /data/backups/food-central-$(date +%F).db`

## What to avoid
- No auth system (solo user — skip it)
- No Docker Compose or multi-container setup — single LXC, single process
- No client-side AI calls — always go through API routes
- Don't over-engineer recipes — plain JSON from Claude is fine, no separate Recipe model unless needed
